# 02 玩法接入与关卡

这款游戏的玩法由哪些文件组成、要遵守的接口、关卡和难度。规则本身在 `docs/01` 第 1 节。局内外壳（顶栏、技能栏、连击满屏、复活、失败、结算、教学、提示、演示、代打）是底座的，照用。

## 1. 玩法由哪几块组成

| 文件 | 层 | 是什么 |
|---|---|---|
| `client/assets/scripts/core/dig/level.ts` | 纯逻辑 | 关卡文件的格式 `LevelFile`、读成 `DigLevel`（`parse`）、数据检查（`problems`）、`kindOf` |
| `client/assets/scripts/core/dig/rules.ts` | 纯逻辑 | 局面 `GameState`（哪颗豆能挖 `diggable()`）、点击 `tap()`、计时 `tick()`、技能 `useSlot()` / `useShunt()`、提示 `hint()`、复活 `revive()`，返回事件列表 |
| `client/assets/scripts/game/board.ts` | 界面 | 料场：每个位置只画最上面那颗豆，被挖走时露出下面的；「透视」 |
| `client/assets/scripts/game/station.ts` | 界面 | 装车位、待发线、车厢、小挖机 |
| `client/assets/scripts/game/gameView.ts` | 界面 | 局内外壳（底座）。标了「玩法」的几处是这款游戏的：`start()` 读关卡、`layout()` 里料场和站台、`doTap()`、`play()` 把事件排到时间上播、`update()` 里提示和代打 |
| `client/assets/scripts/game/flow.ts` | 界面 | 局内流程（底座）。标了「玩法」的几处：`hasEffect` / `useSkill` 的技能效果、`LOSE_KEY` / `REVIVE_KEY` 失败原因、`endRun` 的任务计数、`checkTutorial` 什么时候教新技能 |
| `client/assets/scripts/game/labHooks.ts` | 界面 | 难度调试页的整体三档：装车位加减几个、连击窗口 |
| `client/assets/scripts/services/config.ts` | 服务 | `loadLevel()` 读 `config/levels/level_XXXX.json`、`kindOf()` |
| `client/assets/resources/config/levels.json` | 配置 | 关卡总表：总数、难关间隔、装车位数、复活加时、机关首发关 |
| `client/assets/resources/config/levels/level_XXXX.json` | 配置 | 一关一个文件（生成的，不手改） |
| `client/tools/level/pictures.ts`、`specs.ts` | 工具 | 图库；每一关用哪几幅画、几条待发线、车厢多大、要多难 |
| `client/tools/level/build.ts`、`solve.ts` | 工具 | 关卡生成；求解器和两个机器人量具 |
| `client/tools/level/verify.ts` | 工具 | `./run.sh level-verify`（CI 跑） |
| `client/tests/dig.test.ts` | 测试 | 规则、技能、胜负边界、每一关的文件和参考解 |

## 2. 接口

**纯逻辑**（`core/`，不 import `cc`，不碰时间、存储、`Math.random`）：

```ts
parse(file: LevelFile, 降档 = 0): DigLevel          // 读一关；降档用文件里的 ease 变体
kindOf(cfg, 关卡号): 'normal' | 'hard' | 'boss'

// 局面：就地修改，返回这一步产生的事件；界面只按事件播动画，不自己推导规则
class GameState { status; loseReason; revived; slotAdded; clone(); diggable(); freeSlot(); canTap(); hasHidden(); ... }
tap(s, 第几条待发线): GameEvent[]        // 最前面的车厢进站；点不动返回 []
useShunt(s, 线, 第几节): GameEvent[]     // 技能「调车」
useSlot(s): GameEvent[]                  // 技能「加位」
tick(s, dt): GameEvent[]                 // 限时
hint(s): 该点哪条线 | -1                  // 闲置提示、机器人代打共用
revive(s, 加时秒数): GameEvent[]         // 复活
```

事件见 `docs/01` 第 1.4 节。「透视」只是看，不改局面，没有规则函数。

**界面接口**（`gameView.ts` 给 `flow.ts` 用的）：`s`、`lv`、`arg`、`combo`、`used`、`moved`、`ended`、`paused`、`items`、`departed`、`quiet`、`isPicking`、`doTap()`、`act(fn)`、`resync()`、`xray()`、`startPick()` / `endPick()`、`refreshSkills()`、`showIntro()`、`startTutorial()`。

**连击**：发走一节车厢时调 `hitCombo(x)`，满屏特效、金币、夸奖全部是底座的。

## 3. 改玩法、加机关的步骤

1. 先改 `docs/01` 第 1 节（规则、事件、技能、失败原因），大改先讲给用户、确认后动手（CLAUDE.md）。
2. 改 `core/dig/` 和 `client/tests/dig.test.ts`：每条规则、每个技能、胜负边界各一两个用例。`./run.sh test` 通过。
3. 关卡文件的格式有变就改 `LevelFile`、`parse`、`problems`、`tools/level/build.ts`，重新生成全部关卡。
4. 改 `game/board.ts`、`station.ts`，和 `gameView.ts`、`flow.ts` 里标了「玩法」的地方。技能有变还要改 `economy.json` 的 `skills.order`、`toolPrice`、`toolStart`、`features.skill_<id>`，技能图标 `icon/skill_<id>.png`，文案 `H_SKILL_<ID>`，音效（`services/audio.ts` 的 `MAP`）。
5. 失败原因文案 `UI_LOSE_*`、复活效果 `REVIVE_*`、开局说明 `TIP_*`（挂在 `game_ui.json` 的 `tips`）、加载页小提示 `BOOT_TIP_*`。
6. `./run.sh check`、`./run.sh level-verify` 通过，再去 Mac 上 `./run.sh` 试玩、`./run.sh auto` 让机器人代打一遍。

## 4. 关卡

- **进包的关卡必须可解**（CLAUDE.md）：每关带一条参考解（按这个顺序点车厢一定能过，不用技能），`./run.sh level-verify` 逐关照着打一遍。
- **来源：离线生成的关卡文件**，一关一个 `config/levels/level_XXXX.json`，可以逐关挑、逐关调。微信版放到网上下载（`docs/04` 第 7 节）。
- **关卡文件里有什么**：

| 字段 | 内容 |
|---|---|
| `w`、`h`、`layers` | 从下到上每层一张格子图：`h` 行、每行 `w` 个字符，`.` 空、`#` 石块、`0-9a-z` 颜色编号。上层悬空的豆落到下面（每个位置是一摞）。硬豆、钥匙等机关做的时候再加字段 |
| `palette` | 这一关用到的颜色 |
| `tracks` | 每条待发线上的车厢，从前到后：`c` 颜色、`n` 容量。问号、上锁、连挂做的时候再加字段 |
| `slots` | 装车位数，固定 5（留着字段，不拿它调难度） |
| `kind` | `normal` / `hard` / `boss` |
| `timeLimit` | 限时秒数，不限时不写 |
| `mechanics` | 这一关用到哪些机关（校验器按它检查，也用来查「首发关之前不能出现」） |
| `solution` | 参考解：点击顺序 |
| `ease` | 降档变体：每一档只换 `tracks`（画不变） |
| `name` | 画的名字（上层 / 下层），调试和以后的收藏册用 |
| `meta` | 生成种子、豆数、车厢数、量出来的难度数据（第 5.2 节）、有没有落进目标区间 |

- **怎么生成**（按解构造，`npx tsx client/tools/level/build.ts [起] [止]`；每关用什么画、要多难写在 `specs.ts`）：
  1. 从图库取这一关的画（从下到上），模拟出一个合法的挖豆顺序：每次挑一种现在挖得到的颜色，切出一节车厢，让它装满开走。
  2. 太小的车厢并进同色的另一节（那一节就要在站台上多等一会儿），每并一次都照顺序打一遍确认还能过。
  3. 把车厢按先后分到几条待发线上——照这个顺序点一定能过，这就是最初的参考解。
  4. 朝目标难度一步步打乱：同一条线上相邻两节对调、一节挪到别的位置、两节同色的并成大车厢、大车厢拆开。每一步都用求解器确认有解（参考解换成求解器找到的），用两个机器人量过关率，离目标不更远才留下。换几个起点各找一遍，挑最贴近的。
  5. 降档变体：第 1 档是第 3 步的排法（不打乱、轮流分到各条线）；第 2 档再把大车厢拆成两节。
- 现在生成 10 关要十来分钟（每一步都要量几百局），做 100 关之前要先加速（M2）。
- **图库**：每关两幅有关联的像素图（比如上层蛋壳、下层小鸡），题材用水果、甜点、动物、玩具、节日。画的大小和颜色数按第 5.4 节。图怎么出在 `docs/03`（M2 开始前定）。

## 5. 难度

### 5.1 难度从哪里来

这类玩法难不难，看的是**玩家有多容易叫错车、把装车位占满**。旋钮按影响从大到小：

1. **错位度**：车厢排队的先后，和画「由外到内、由上到下」能挖到的先后错开多少。错得越多，待发线最前面越常是「现在挖不到的颜色」。
2. **车厢大小**：大车厢要很久才装满、长时间占位；小车厢来去快。
3. **颜色数**：颜色越多，5 个装车位越不够分。
4. **层数和遮挡**：要的颜色压在下层；下层看不见。
5. **画的大小**：豆越多，一局越长，中途出错的机会越多。受单局时长限制，不能一直加。
6. **机关**（`docs/01` 第 1.7 节）。
7. **限时**：只给难关、超难关，从第 10 关起。

装车位固定 5 个，是玩家心里的尺子，不动。

### 5.2 怎么量

只用屏幕上看得到的信息：

| 量具 | 是什么 | 说明什么 |
|---|---|---|
| 随手点 | 随机点一节点得动的车厢 | 不动脑能不能过 |
| 稳妥点 | 只叫现在有豆可挖的颜色（有多节就叫能装得最多的）；没有这样的车厢才随机点 | 按常识玩能不能过。也是 `hint()`、闲置提示、`./run.sh auto` 代打用的 |
| 最少占位 | 求解器算：所有解法里，最紧的时刻最少要占几个装车位 | 2–3 宽松，5 是一步不能错 |

每关各跑几百局，结果记进关卡文件的 `meta`。求解器只用来保证有解和算「最少占位」，不拿它当难度。

### 5.3 各类关卡的目标

| 关卡类型 | 随手点过关率 | 稳妥点过关率 | 最少占位 |
|---|---|---|---|
| 教学关（技能、机关的首发关） | 100% | 100% | 1–2 |
| 普通关 | 按阶段，见第 5.4 节 | 第 1–30 关 100%，之后不低于 80% | 2–4 |
| 难关（每 5 关） | 10%–20% | 50%–70% | 4–5 |
| 超难关（每 10 关） | 低于 10% | 30%–50%（要看后排车厢提前规划） | 5 |

新手阶段（第 1–10 关）的难关、超难关放宽：第 5 关随手点 25%–45%、稳妥点 70%–90%；第 10 关随手点 10%–30%、稳妥点 60%–85%。刚学会玩就碰到上表那么难的关，容易直接走人。

好的难关是「想清楚能过、随手点会输」。

### 5.4 阶段

难度按**阶段**定，不按关卡号一直涨：第 30 关左右到顶，以后的关卡（包括以后更新的）都落在「平台」这一档。

| 阶段 | 关卡 | 普通关随手点过关率 | 颜色 | 每层大小 | 车厢数 | 待发线 |
|---|---|---|---|---|---|---|
| 新手 | 1–10 | 100% 降到 80% | 3–4 | 10×10 到 12×12 | 6–10 | 2，第 6 关起 3 |
| 爬坡 | 11–30 | 70% 降到 45% | 4–6 | 12×12 到 16×16 | 10–16 | 3 |
| 平台 | 31 关以后 | 35%–45% | 5–7 | 14×14 到 18×18 | 12–20 | 3 |

单局时长：普通关 40–90 秒，难关 2 分钟以内（按「稳妥点」机器人加动画时间估）。超了就把画改小或把车厢合并，不靠玩家开倍速。

### 5.5 节奏

- **5 关一组**：易、易、中、中、难；难关、超难关后面一关固定是轻松关。
- **20 关一章**，首版 5 章 100 关；章只换背景和题材，不代表难度台阶。
- `levels.json`：`hardEvery` 5、`bossEvery` 10；`total` 是现在做好了几关（原型阶段是 10，首版做到 100）。
- **连输降档**（`easeAfterFails`）：换成关卡文件里 `ease` 的下一档——车厢顺序往参考解靠一步，或把一节大车厢拆成两节；画不变。

| 关 | 内容 |

| 3 | 被围住的颜色挖不到，叫早了占位 |

| 6 | 双层画首发（教学关），待发线变 3 条 |

## 6. 以后怎么加关卡和机关

- **加关卡就是加文件**：新的 `level_XXXX.json` 加进去，改 `levels.json` 的 `total`。难度照第 5.3、5.4 节「平台」一档的区间，用同一套量具量，不用重新设计曲线。
- **按关卡包更新**：一包 20 关（一章），带 1 个新机关和一批新画。
- **机关各自独立**：每个机关是规则里单独的一块（能不能挖、能不能点、挖走时触发什么），加新机关不改已有的；关卡文件用 `mechanics` 声明用了哪些。
- **首发关写在配置里**：`levels.json` 的 `mechanicFrom`（机关 → 第几关首发）。想把某个机关提前或推后，改这里和对应的关卡文件；`level-verify` 检查「首发关之前没有关卡用到它」。
- **打完现有关卡**：照底座在后一半关卡里循环（`docs/01` 第 4.12 节），直到新关卡包上线。
- **怎么发**：微信版关卡文件在网上，更新不用重新提审；iOS、Android 跟着新版本发。
- **看数据再调**：上线后按每关的通过率、流失调 `ease` 和个别关卡文件，不动规则。
