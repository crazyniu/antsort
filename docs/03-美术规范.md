# 03 美术规范

分工：**AI（Claude）写出图需求、写程序画的部件、做切图和进包；Codex 出全部位图插画；用户定风格和验收。** 界面的配色、字体、部件、版式见 `docs/09`，这里只管图怎么来、怎么进包。

## 1. 原则：同品类观感，原创设计

参考同类游戏只用来确定**品类气质**（明亮、圆润、高饱和的卡通休闲风，大字，厚实的按钮）。除此之外全部原创，**不得**：

- 照着任何现有游戏的截图画角色、图标、场景、标题字、界面布局；
- 用现有游戏、动画、电影的角色名、场景名；
- 把别的游戏的截图当图生图的输入喂给 Codex（风格参照只能用我们自己的图）。

原因不只是规矩：微信、Google Play、App Store 都会因美术雷同下架甚至封号，软著和商标也过不了。

## 2. 新游戏先定什么（开工时写进这一节）

| 维度 | 新游戏的设定 |
|---|---|
| 主题和世界观 | TODO（例：海底、森林、甜品店、太空……） |
| 主角 / 吉祥物 | TODO（团子比例、大眼睛高光点、无牙无刺这类可爱规矩可以沿用） |
| 场景色调 | TODO：背景比前景安静，景物放两边和底部，中间留给玩法；颜色压低，不和玩法元素撞色 |
| 界面主题色 | 默认宝蓝平面风（`docs/09` 第 2 节）；换色改 `tools/art/flat_skin.py` 的颜色表和 `ui/kit.ts` 的 `INK`、`PART_INK` 的深色，重新生成部件图 |
| 风格锚定图 | `art/style/anchor.png`：用户从 3 套样张里选定一张，之后所有出图都附它做参照 |

底座的界面是**平面纯色**（否决过亮面果冻风、整条深色底栏、大圆角胶囊按钮、白卡片配蓝字整页铺满、轻玻璃半透明、糖果粗描边套框），新游戏沿用，不重新设计。

## 3. 资源规格

| 类别 | 尺寸（像素） | 格式 | 位置 |
|---|---|---|---|
| 设计分辨率 | 750 × 1334 | — | 竖屏，图片都是 3 倍图（显示尺寸 = 像素 / 3） |
| 收藏卡 / 玩法图案 | 360 × 360（显示约 120） | PNG 透明，256 色 | `client/assets/resources/card/<id>.png`，统一朝向、留 8px 透明边 |
| 图标（入口、技能、金币、宝箱……） | 288～384 方 | PNG 透明，256 色 | `resources/ui/icon/`；一套技能图标在 Codex 的一张图里一起画（大小、粗细、光影一致），再切开 |
| 主页 / 章节背景 | 1024 × 1536 | JPG 质量 85 | `resources/ui/bg/home.jpg`、`chapter_<id>.jpg` |
| 加载页背景、logo | 750 × 1334 / 约 900 × 360 | JPG / PNG | `client/assets/boot/`（打进安装包，越小越好） |
| 应用图标 | 1024 × 1024 | PNG | `art/approved/logo/logo_1024.png` → `./run.sh native-icons` 生成各平台尺寸和 iOS 启动屏 |
| 平面界面部件 | 程序画 | PNG | `resources/ui/skin/f_*`、`j_btn_*`，`python3 tools/art/flat_skin.py` |
| 特效小件（光、环、星、彩纸） | 程序画（SVG） | PNG | `resources/ui/kit/`，`node client/tools/art/kit.mjs` |
| 艺术字（连击数字、夸奖词、「连击」） | Codex | PNG | `resources/ui/skin/j_dg_*`、`j_praise_1..4`、`j_combo_word`（夸奖词和「连击」带中文，只在中文下用，其它语言用字） |
| 上架图 | 见 `docs/06` 第 7 节 | PNG | `store/images/`（`./store/gen.sh` + `tools/store/export.py`） |

- 单张贴图 ≤ 2048 × 2048；进包的 PNG 一律量化成 256 色调色板（`./run.sh art-compress`，`./run.sh check` 会查）。
- 界面能用代码画的就不用图片（包体）：面板、按钮、条、格子、光圈都是程序画的；位图只留角色、卡面、图标、背景和少量主视觉。
- 文字不画进图里（多语言要换字）；例外是只在中文下用的艺术字、上架图。
- 命名全小写下划线。

## 4. 角色与收藏卡的设计规则

- **玩法里同屏的图案必须一眼分清**：按主色的色差（Lab 色差）和轮廓去重，不看颜色名字。验收：缩到 64px、转灰度，同一关可能同屏的两两仍能分清。
- **稀有度越高越特别**：普通朴素；精良带一件小饰品；稀有加珍珠、花冠、一圈柔光；史诗要比别的都好看（宝石、王冠、星空花纹、发光）；传说金色花纹星芒。卡框按稀有度配色（`docs/09` 第 2 节）。
- 名字原创，两到三个字，口语可爱；每种语言各起一套，不和现有游戏、角色重名，避开各地粗话（`docs/10` 第 8 节）。
- 清单写进 `config/cards.json` 和文案 `CARD_<ID>`，用户过目后再开画。

## 5. Codex 出图流程

```
art/
  briefs/     # AI 写的出图需求，一个资源（或一批）一份
  style/      # 风格锚定图：用户验收过的样张，之后出图都附它做参照
  raw/        # Codex 原始产出（不进仓库）
  approved/   # 用户确认可用的源图（应用图标等）
```

1. **风格锚定**（只做一次）：AI 按第 2 节写 brief，Codex 出 3 套风格样张（各含 3 个角色 + 1 个图标 + 1 张背景局部），用户选定一套存 `art/style/anchor.png`。
2. **批量出图**：AI 写 brief → Codex 出图到 `art/raw/` → AI 检查规格（尺寸、透明底、朝向、辨识度、有没有字）→ 不合格附原因重出。
3. **验收**：一批拼一张总览图给用户看，放大到 200% 查边缘。
4. **进包**：切图、缩放到规格（Lanczos、线性空间、透明图先预乘）→ 放进 `client/assets/resources/` → `./run.sh art-compress` → `./run.sh meta`。

调用方式：

```bash
cd art/raw/<批次>
codex exec --skip-git-repo-check --sandbox workspace-write --image=../../style/anchor.png -- "<英文出图描述>. Use your image generation tool. Reply with only the saved file path."
```

- 图存在 `~/.codex/generated_images/<会话 id>/*.png`，路径在输出最后一行，自己拷回 `art/raw/`。一次一张，约 4 分钟；多张并行跑多个进程。
- 描述用英文，写明「no text, no watermark, do not reference any existing game」。
- 要透明底：让 Codex 出纯色底（品红 `#FF00FF` 或纯白），按颜色混合比例还原半透明边缘；**禁止硬阈值抠图**（会有锯齿和白边）。一张图多个元素时写明「元素互不接触、无落地阴影」，再按连通区域切开。

brief 模板：

```markdown
# card_c01 <名字>
- 用途：收藏卡 / 玩法图案，360×360 透明底，朝左
- 主色：<颜色>；轮廓类：<圆 / 扁长 / 星形 …>（和同一章的其它卡分开）
- 造型：<一两句>
- 风格参照：art/style/anchor.png（只参照质感与比例）
- 禁止：文字、水印、背景、落地阴影、写实纹理、任何现有游戏的角色
```

## 6. 清晰度

- 源图至少是最大显示尺寸的 2 倍（界面插画按 3 倍）；缩小用 Lanczos、在线性空间里做。
- 透明边要有半透明过渡，不用硬阈值。
- `.meta` 由 `./run.sh meta` 生成：线性过滤 + mipmap（缩小显示不出锯齿）、修透明边。
- 每批图出来先拼总览、放大检查，再给用户看。

## 7. 动画约定

实现集中在 `client/assets/scripts/ui/fx.ts`，新界面复用，不各写各的（清单见 `docs/09` 第 4 节）。

| 场景 | 动画 |
|---|---|
| 进页面 | 部件依次弹出，总时长 ≤ 0.8 秒 |
| 待机 | 主页展示区一直在动；主按钮呼吸；有红点的入口隔一会晃一下 |
| 点击 | 按下缩 0.95～0.96 并压暗，松手回弹；点不了的东西晃一下 + 错误音 |
| 局内 | 点中回弹、飞行带弧线、命中有光和火花；连击满屏（`docs/09` 第 8 节） |
| 奖励 | 金币飞向余额、数字滚动；宝箱晃动弹开；新卡翻面，稀有以上加金光彩纸 |
| 失败 | 整屏晃动；弹窗缩放回弹 |
